# CLAUDE.md

Instructions for Claude Code working in this repository.

## What this repo is

`ml-lab` (formerly `llm-lab`) is Zihan Xu's portfolio of hands-on machine learning projects. Each project lives in its own folder and is self-contained, with its own README, requirements, scripts, tests and results.

Current project: `camera-breathing/`, a study of how video compression affects camera-based breathing measurement, compared with heart-rate measurement on the same videos, and how to make it more robust. The plan, experiments, phases and acceptance criteria are in `camera-breathing/GUIDE.md` (written in Chinese). Read it before any task in that folder. Work on one phase at a time. Don't change the plan on your own; propose changes in the PR description.

## Where code runs

- Cloud sessions have no GPU (4 vCPU, 16 GB RAM, 30 GB disk, Ubuntu x86_64) and can't download the datasets. Never start full experiment runs in a session.
- The owner downloads data and runs experiments on Google Colab Pro, then pushes the results. Notebooks are thin launchers: they mount Google Drive, clone the repo, install requirements and call scripts, and all logic lives in the repo. Colab can disconnect at any time, so long jobs process one video at a time, record their progress and resume where they stopped.
- Datasets go straight into Colab, never through the owner's computer and never into git. Scripts process videos one at a time and delete them after extracting signals; only signals and results are kept, on Google Drive.
- The owner's own computer runs nothing.
- Everything must be testable on CPU without the real datasets. Tests use small synthetic videos generated by code with known breathing and heart rates, never real recordings.
- Core modules (signal extraction, rate estimation, reference processing, metrics, compression settings) must not import torch. Only the optional deep model in phase 5 uses torch.
- If a download fails because the network allowlist blocks a host, report it instead of working around it.
- Target Python 3.10–3.13. Cloud sessions run 3.13; check Colab's Python version before pinning dependencies.

## Rules

1. Never invent numbers. Every number in a README, note or PR must come from a file under `results/`. If that file doesn't exist yet, write TODO.
2. Never commit datasets, videos, frames, model weights, checkpoints or files over about 5 MB. Don't commit signals extracted from licensed datasets either; keep them on Google Drive. Commit code, configs, per-video results (estimated rates and errors), aggregated metrics, figures and notes.
3. Never commit or publish images or video of real people from any dataset. Figures may show synthetic frames (SCAMPS) or the owner's own frames only.
4. Respect each dataset's license: research use only, no redistribution. Record each dataset's terms in `notes/`.
5. Every run writes `results/<run_id>/` with the full effective config, git commit hash, package versions (including ffmpeg and MediaPipe), hardware and metrics. Run IDs look like `20261101_scamps_x264-ladder`; add `_s0` for runs that use a random seed.
6. All experiments share one evaluation protocol (GUIDE.md §4.4): region detection, signal extraction, filter bands, window lengths, rate estimation, compression settings and metric code. Changing it invalidates earlier results. If a change is unavoidable, record it in `notes/` and re-run the affected experiments.
7. Nothing from the owner's internship: no code, data or parameters from iFlytek. Write everything from scratch, based on public literature only.
8. ffmpeg, OpenCV, MediaPipe and PyTorch behave differently across versions. Check the docs for the installed versions, record the versions in every run, and pin them once a setup works.
9. Keep core logic in small, pure, unit-tested functions, with thin adapters for ffmpeg, MediaPipe and dataset formats.
10. Before opening a PR, make sure `ruff check`, `ruff format --check` and `pytest` all pass.

## Pull requests

- One phase, or one clearly scoped task, per branch and PR.
- The description covers what changed and checks off the phase's acceptance criteria from GUIDE.md one by one. If the next step needs Colab, it also gives the exact commands the owner should run there, ready to copy.
- End every PR description with a `学习要点` section in Chinese: 3–6 bullets that explain the key concepts and design choices, and what the owner should be able to explain in an interview.
- When the owner pushes results, sanity-check them before building on them. Flag anything suspicious, such as non-zero error on synthetic videos with known rates, better results on compressed video than on the uncompressed original, or a reference signal that disagrees with itself.

## Language

Code, comments, commit messages and READMEs are in English. Notes under `notes/` and the `学习要点` sections are in Chinese.
